## 2 必须优先处理的问题

### 2.1 训练与专项测试混用了特征版本

严重程度：高，直接违反题目明确要求。

`problem2_bert_fusion_train.py:300` 固定加载附件二 `aligned_50.pkl`，而 `:415` 遍历 aligned 与 unaligned 两套附件三。`problem2/train.py:241`、`:317` 也存在相同路径。`problem2/data.py:129` 把 unaligned 音视频的 500 行平均为 50 行，不能据此认为它已等价于官方 aligned 特征。

题目要求训练、验证和专项测试保持同一版本、同一接口。更进一步，当前重采样按整个存储长度分箱，某个箱只要还有一个非零行就被标为有效，原来的局部缺失长度会被压缩甚至隐藏；长尾填充也混入分箱边界。所生成 unaligned 预测不能与 aligned 预测一起作为同一套合规建模结果提交。

处理建议：沿用当前 aligned 训练路线时，只保留 aligned 附件三作为正式专项结果；现有 unaligned 文件明确标为非正式跨版本探索。若选择 unaligned 路线，应从附件二 unaligned 开始训练、验证，统一全部预处理，并处理有效长度。题目允许二选一，没有要求必须提交两套。

### 2.2 问题二缺少题目规定的主要实验

严重程度：高，影响“问题二已经完成”的认定。

当前主模型为 `problem2/bert_model.py` 中的 `BertAVFusion`：BERT 有效 token 均值加音视频有效帧均值、标准差、有效比例，然后联合分类和回归。`problem2_bert_fusion_train.py:352` 开始的训练循环直接使用原始训练 batch，没有调用局部连续遮挡，也没有缺失重建或一致性损失。

这并不意味着该模型必然不鲁棒：掩码池化本身可能有所帮助。但**有掩码、能输出附件三预测、干净测试准确率达到 71.80%，都不能代替缺失条件下的性能证据**。旧 Hybrid/gated 模型的增强机制也不能被写成所选 BERT 模型的训练方案。

现有目录未发现按缺失模态、缺失率、缺失位置、连续段长度组织的受控结果，也没有同一架构“有/无缺失增强”的配对消融。阶段报告最后一节对此有诚实说明，应保留。

### 2.4 问题一的特殊词元被错误用作局部时间证据

严重程度：中高，影响时序对应的可信度。

`problem1/pipeline.py:190` 将没有字符跨度的特殊词元映射到第一个或最后一个 CTC 词段，随后参与时间池化。`[CLS]`、`[SEP]` 并不是在这两个时段真实说出的词，其上下文表示也不能当成该局部词段的专属观测。

截断样本使问题更明显：已有审计记录 6/100 条被截断，共省略 70 个 token。例如 `-AUZQgSxyPQ$_$2` 的倒数第二个已存 token 对应约 18.480–18.941 秒，但 `[SEP]` 被放到全文最后一个词 CELLS 的 21.544–21.824 秒；尾部文本并未完整送入 BERT，却出现了来自 `[SEP]` 的有效文本时间覆盖。

建议：特殊词元不参加局部时间池化，可单独保留全局表示；真实子词按字符跨度映射到对应词段。修正后至少重新生成文本特征、掩码、覆盖率、典型样本与全量汇总。对数字、标点等没有 CTC 词跨度的 token，也应使用明确规则并单独记录，不宜按 token 序号粗略映射到某个词。

同时，`problem1/report.py:204`、`:471` 将“50 个文本位置”表述为问题一的强制要求，这不准确。题目规定的 50 是附件二输入接口；问题一允许自行设计时序特征，只须说明组织与对齐规则。即使最终输出仍保留 50 个时间 bin，也可以先编码更长或分块文本，再池化至 50 个 bin。应把当前截断写成方法选择，并补充截断影响或修正方案。

### 2.5 旧模型的局部遮挡可能把短样本整模态清空

严重程度：中高，继续使用旧训练器时需要修正。

`problem2/data.py:107–125` 在固定 50 个位置上抽取遮挡区间，不以原始有效区间为基准，也不保证仍有有效位置。因此它可能只遮挡 padding、达不到期望缺失率，也可能覆盖一个短模态的全部有效信息。

已执行现有函数体的确定性分支检查：初始仅前 5 行有效，选择局部块 `[0,10)` 后，有效行数变为 0。此检查用 NumPy 数组和确定性随机数替身执行原函数体，不是 PyTorch 训练测试。问题不是抽样范围为 50 本身，而是未对“有效信息仍有剩余”设约束；代码注释中的“No complete-modality dropout”无法保证。

应在真实有效区间内采样连续块，报告相对原有效位置的新增缺失率，并保证局部任务下每个被遮挡模态仍保留有效观测。必须区分自然填充、原始缺失与人为新增缺失。

### 2.6 模型选择口径尚需统一

严重程度：中，涉及评价协议。

当前脚本在单次运行内按验证 Macro-F1 选模，训练统计量也仅来自训练集，核查没有发现直接用测试标签优化参数的代码。但报告明确承认历史开发多次查看测试分数；不能再把这批 test 表述为从未使用过的最终盲测。

还应解释为何选定 reproduce 模型：其验证 Macro-F1 为 0.61054，而 history 模型第 16 轮为 0.61597，旧 `problem2_outputs` 的验证 Macro-F1 为 0.62241。后两者测试分数低，不构成按题意放弃它们的理由。这不是证明存在标签泄漏，而是说明“测试准确率最高”与“按验证指标选择”不是同一标准。

可将 reproduce 明确固定为历史基线；后续以事先确定的验证指标和实验预算比较候选模型。问题二应同时考虑干净性能和受控缺失性能，保存模型选择依据。30 轮复现记录的第 16 轮验证分数略高于第 2 轮，也意味着 README 中“2–5 轮达到峰值”不能当作所有后续实验的普遍结论。

## 3 问题一需要补充的验证与说明

### 时间长度差异需要解释，但目前不能认定原视频被删改

题目给出的 2.648–34.567 秒与本次直接读取 100 个 MP4 的 movie header 完全一致。已有报告写 2.260–29.290 秒，95/100 条保存时长与容器时长相差超过 0.05 秒，最大差 8.294 秒。

继续检查发现，视频包含 MP4 编辑列表，其有效呈现区间明显短于容器媒体长度。例如 `-uywlfIYOS8$_$4`：容器 14.334 秒，视频编辑列表呈现时长 6.045 秒，保存时长 6.04 秒；媒体起点约 8.355 秒，音轨编辑起点约 8.376 秒。**这支持时长口径差异的解释，不支持直接指控样本被替换或人为截短。**100 个视频的文件哈希也与原提取清单一致。

但当前报告未说明这一点，且保存时长与视频编辑列表时长仍有 9 条相差超过 0.02 秒，最大约 0.097 秒；不同轨道的起点和有效长度也可能不同。应补导出每条视频的容器时长、视频/音频有效起止、PTS、解码时长、统一零点及误差，明确采用的 FFmpeg 编辑列表行为。此次只核查容器与编辑列表，没有重新解码全部音视频，不能据此宣称已测得真实的音画同步误差。

### 对齐展示已有，定量准确性仍缺证据

典型样本图已查看，确实包含真实波形、词段及帧图。覆盖率重建也与保存结果一致。但覆盖率衡量“区间占用”，不衡量 CTC 起止时间是否正确。建议对至少一组不同长度、语速及低置信度样本人工核对词边界，报告起止误差、误差分布与失败案例；优先覆盖 6 条截断样本和时长口径差异明显的样本。

本次按保存的 float32 时间边界重新计算源索引，在 15 个“样本×模态”组合上出现极小边界重叠带来的索引差异；所有对应掩码和覆盖率在 1e-4 容差内一致。它不是实质性错位证据，建议统一保存精度及零重叠容差以提高可复现性。

### 音频与视觉特征的情感相关性需要论证

74 维音频为自定义波形/频谱描述，35 维视觉为低分辨率全帧颜色、纹理与直方图统计；维度碰巧与附件二一致，不能说明其特征语义相同。不得把问题一特征直接当成官方附件二特征输入已训练的问题二模型。

问题一没有强制要求某个面部表情网络，也没有指定必须达到某个分类准确率，因此不能仅因使用手工特征就判定不合题意。但全帧颜色和背景信息是否有效反映情绪，目前缺少实验。建议用题目已有数据做描述性相关分析或谨慎的分组交叉验证，对比当前视觉描述与面部/动作相关特征、当前音频描述与韵律特征。100 条样本中 Positive 有 57 条，不能用多数类准确率或训练集拟合分数证明有效性；按 video_id 分组可减少同源片段干扰。该实验是对方法合理性的补强，不是题目额外规定的硬性指标。

## 5 最小补实验方案

### 问题二必须补做

1. **固定协议。**选定 aligned 路线，在训练集学习参数，在验证集选择模型、缺失增强强度与阈值；附件三仅做最终推理。保存每次实验的配置、数据哈希、种子和模型权重。
2. **建立受控局部缺失评估。**以验证集原本有效的信息为基准，在同一批样本上生成配对遮挡。建议缺失比例为 0%、10%、20%、30%、40%；分别考察 T、A、V、TA、TV、AV、TAV；覆盖前段、中段、后段、随机位置，以及单段/多段。先做单因素曲线，再选择若干交互组合，避免无必要的全笛卡尔积。
3. **明确长度的含义。**附件二没有逐词物理时间戳，缺失比例应写成有效序列位置比例，连续长度写成有效位置数；没有真实时间映射时不能把它直接称为“缺失几秒”。生成文本遮挡时要同步更新 token、attention mask 或连续文本特征，不能从完整 raw_text 补回已删除内容。
4. **同架构消融。**至少比较 BERT AV 原模型、有局部连续缺失增强的同架构模型，以及与所提改进直接相关的去组件版本。文本单模态、简单融合和小型鲁棒模型可作为补充基线，但需重新按相同协议训练并保存结果。
5. **报告完整指标。**每种条件报告 Accuracy、Macro-F1、MAE、Pearson，相对完整输入的性能下降、实际有效缺失比例和有效样本数；掩码使用多个固定种子。算力允许时对关键模型做至少 3 个训练种子，并报告均值及波动。附件三无真实标签，不能报告其准确率，也不能把两版本预测一致率当作鲁棒性评价。
6. **补验证集错误归因。**选中性误判、极性反转、强度大误差和遮挡后新出现的错误，结合转写与可获得材料进行人工核查，区分可证事实和解释假设。

### 问题一建议补做

优先修正特殊词元时间映射；对长文本比较当前 50-token 截断与完整/分块编码后池化；记录 MP4 编辑列表及实际解码时间轴；完成一组人工词边界核对。情感相关特征比较随后进行，避免把大量时间用于重新绘制已齐全的统计图。

### 问题三尚需完整开展

在附件二训练/验证协议下建立可解释预测流程，输出类别与强度、三模态贡献、主要参考模态、模态内部局部重要性及原素材证据。至少完成典型解释卡、模态/局部重要性图、附件四所选版本全部 20 条预测与解释 CSV，以及验证集基础评价与错误归因。

需要以遮挡删除、重要片段保留、随机片段对照或类似方法验证解释是否忠实；注意力/门控数值本身不能自动证明贡献。附件四提供原视频，但附件二式的 50 个序列位置不自带秒级时间戳，不能直接以 `k×视频时长/50` 冒充原始证据时间。应明确建立 token/帧/音频段与原视频之间的对应关系。

### 建议处理顺序

先迁回权重并明确模型与版本，再修正缺失语义和问题一时间映射；随后完成问题二的必需缺失实验，同时推进问题三。最后整理论文正文、配置与运行说明，核算总附件 ≤50 MB。当前问题一输出清单约 20.6 MiB，只是问题一目录的大小，不能代表包含两类专项模型的完整提交包。

## 6 审核文件与复核方式

本目录中的 `evidence.json` 保存全量样本检查、两类专项数据字段、预测重算、划分互斥与哈希结果；`media_timeline_evidence.json` 保存 100 个原视频的容器/编辑列表时序；`unaligned_evidence.json` 保存 unaligned 数据结构和数值检查。

`verify_artifacts.py` 可用具备 NumPy、OpenPyXL 的 Python 运行，只读原数据与成果，更新本目录的 `evidence.json`；`probe_media_timeline.py` 随后复核 MP4 时间头和编辑列表。它们不需要下载模型，也不执行训练。审核脚本中的确定性遮挡分支检查使用随机数替身，不能替代完整 PyTorch 单元测试。

本审核没有把缺失的模型或实验推定为不存在于其他机器，也没有把“未发现泄漏代码”扩大为对整个历史开发过程的保证。完成状态只对应本次实际可查的目录。
